Algorithm Documentation

Data Structures Used

1. Queue (FIFO - First In First Out)

Implementation: collections.deque

Purpose: Manages normal (non-priority) tokens in FCFS order

Operations:

  • enqueue() - O(1): Add token to back
  • dequeue() - O(1): Remove token from front
  • peek() - O(1): View front token

2. Priority Queue (Min-Heap)

Implementation: heapq

Purpose: Manages priority tokens (Emergency > Staff > Student)

Operations:

  • push() - O(log n): Insert with priority
  • pop() - O(log n): Remove highest priority
  • peek() - O(1): View highest priority

3. Stack (LIFO - Last In First Out)

Implementation: Python list

Purpose: Stores skipped tokens for recall

Operations:

  • push() - O(1): Add skipped token
  • pop() - O(1): Recall most recent skip

4. HashMap (Dictionary)

Implementation: Python dict

Purpose: Fast token lookup and rating storage

Operations:

  • insert() - O(1) average
  • lookup() - O(1) average
  • delete() - O(1) average

Algorithms Implemented

1. Merge Sort

Time Complexity: O(n log n)

Space Complexity: O(n)

Purpose: Sort queue views by various criteria

How it works: Divide array into halves, recursively sort each half, then merge sorted halves.

2. Waiting Time Prediction

Time Complexity: O(1)

Formula: waiting_time = (position - 1) × avg_service_time

Purpose: Predict estimated wait for each token

3. Load Balancing (Shortest Queue First)

Time Complexity: O(n) where n = number of counters

Purpose: Assign tokens to least-loaded counter

How it works: Iterate through counters, find one with minimum queue length.

4. Skip & Recall

Skip: O(1) - Push to stack

Recall: O(log n) - Pop from stack and reinsert into priority queue

Purpose: Handle customers who aren't ready when called

5. Rating Analytics

Time Complexity: O(n) for average calculation

Purpose: Aggregate and analyze service ratings

Metrics: Average rating, distribution, total count per department
